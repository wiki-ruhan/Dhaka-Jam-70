# ঢাকা মেট্রোপলিটন এলাকার যানজট গবেষণা: ৩০ দিনের স্বয়ংক্রিয় স্ন্যাপশট সিস্টেম

## অংশ ১: গবেষণা পরিকল্পনা

**লক্ষ্য:** Google Maps-এর ট্রাফিক রঙ (সবুজ, কমলা, লাল, গাঢ় লাল) ব্যবহার করে ৩০ দিন ধরে পুরো ঢাকা মেট্রোপলিটন পুলিশ (DMP) এলাকার যানজট মাপা। ফলাফল DMP-এর ৮টি ট্রাফিক বিভাগ অনুযায়ী ভাগ করা হবে, আর প্রতিদিনের যানজটের সম্ভাব্য কারণ খোঁজা হবে।

**গবেষণা প্রশ্ন:**
1. কোন ট্রাফিক বিভাগে সবচেয়ে বেশি এবং সবচেয়ে কম যানজট হয়?
2. দিনের কোন সময়ে যানজট সবচেয়ে বেশি হয় (সকাল ও সন্ধ্যার পিক)?
3. কর্মদিবস আর সাপ্তাহিক বা সরকারি ছুটির দিনের মধ্যে পার্থক্য কতটা?
4. বৃষ্টি, হরতাল বা অবরোধ, মিছিল, দুর্ঘটনা, জলাবদ্ধতা যানজটকে কতটা বাড়ায়?

**এলাকা:** আপনার আঁকা সীমানা অনুযায়ী, উত্তরে আশুলিয়া ও টঙ্গী, পূর্বে পূর্বাচল, তারাবো ও কাঁচপুর, দক্ষিণে নারায়ণগঞ্জ, পশ্চিমে কেরানীগঞ্জ, আমিনবাজার ও বিরুলিয়া। মোট প্রায় **৫৪০ বর্গকিমি**:

| অংশ | আয়তন (আনুমানিক) |
|---|---|
| DMP-এর ৮টি ট্রাফিক বিভাগ | ~৩০৫ বর্গকিমি |
| DMP-এর বাইরের ৯টি এলাকা: আশুলিয়া, বিরুলিয়া, আমিনবাজার, টঙ্গী, পূর্বাচল, রূপগঞ্জ–তারাবো, কাঁচপুর–সিদ্ধিরগঞ্জ, নারায়ণগঞ্জ ও ফতুল্লা, কেরানীগঞ্জ | ~২৩৪ বর্গকিমি |

DMP-এর বাইরের এলাকাগুলোর আলাদা স্কোর হয়, তাই DMP-এর হিসাবের সাথে মিশে যায় না। সীমানা বদলাতে চাইলে `config.py`-এর `STUDY_POLYGON` অংশে স্থানাঙ্ক বদলান।

## অংশ ২: শুধু ফোন দিয়ে সেটআপ (কম্পিউটার লাগবে না)

সিস্টেমটি GitHub-এর ফ্রি ক্লাউড সার্ভারে চলে। তাই আপনার ফোন বা কম্পিউটার বন্ধ থাকলেও কাজ চলতে থাকবে। খরচ নেই।

**যা লাগবে:** একটি Google অ্যাকাউন্ট (Drive-এর জন্য), একটি ফ্রি GitHub অ্যাকাউন্ট, আর ফোনে Chrome ব্রাউজার।

> টিপ: নিচের ওয়েবসাইটগুলো ফোনে খোলার পর Chrome-এর ⋮ মেনু থেকে **"Desktop site"** চালু করুন। তাহলে সব বাটন ঠিকমতো দেখা যাবে।

### ধাপ ১: zip ফাইল খুলুন
ডাউনলোড করা `dhaka-traffic.zip` ফোনের **Files** অ্যাপে খুলে **Extract** করুন।

### ধাপ ২: Google Drive-এর সাথে সংযোগ (Apps Script)
1. Chrome-এ **script.google.com** খুলুন এবং **New project** চাপুন।
2. সেখানে আগে থেকে থাকা কোড মুছে দিন। তারপর zip থেকে `Code.gs` ফাইলটি খুলে পুরো লেখা কপি করে পেস্ট করুন।
3. প্রথম লাইনের `TOKEN`-এর মান বদলে নিজের একটি গোপন শব্দ দিন। উদাহরণ: `dhaka-2026-x7k9q`। এটি মনে রাখুন বা কোথাও লিখে রাখুন।
4. 💾 **Save** চাপুন।
5. **Deploy → New deployment** চাপুন। ⚙️ থেকে **Web app** বেছে নিন।
   - Execute as: **Me**
   - Who has access: **Anyone**
6. **Deploy** চাপুন, তারপর **Authorize access** চাপুন এবং নিজের অ্যাকাউন্ট বেছে নিন।
7. সতর্কবার্তা দেখালে **Advanced → Go to project (unsafe) → Allow** চাপুন। এটি আপনার নিজের বানানো স্ক্রিপ্ট, তাই নিরাপদ।
8. যে **Web app URL** দেখাবে (`https://script.google.com/macros/s/.../exec`), সেটি কপি করে রাখুন।
9. পরীক্ষা: URL-টি ব্রাউজারে খুলুন। `"ok":true` লেখা দেখালে সংযোগ ঠিক আছে।

### ধাপ ৩: GitHub-এ রিপোজিটরি বানান
1. **github.com** এ লগইন করুন, তারপর **+ → New repository** চাপুন।
2. নাম দিন `dhaka-traffic`, **Public** বেছে নিন, তারপর **Create repository** চাপুন।
   - Public কেন: Public রিপোতে GitHub-এর সার্ভার সময় সীমাহীন ফ্রি, আর ড্যাশবোর্ডের লিংকও ফ্রিতে চলে। ছবিগুলো আপনার Drive-এ থাকবে, GitHub-এ শুধু সংখ্যার তথ্য থাকবে।

### ধাপ ৪: ফাইল আপলোড
1. রিপোর পেজে **Add file → Upload files** চাপুন।
2. zip থেকে এই ৭টি ফাইল একসাথে বেছে নিন: `analyze.py`, `collector.py`, `config.py`, `runner.py`, `dashboard_template.html`, `requirements.txt`, `collect.yml`
3. **Commit changes** চাপুন।

### ধাপ ৫: collect.yml সঠিক ফোল্ডারে সরান
1. রিপোতে `collect.yml` ফাইলটি খুলুন, তারপর ✏️ (Edit) চাপুন।
2. উপরে ফাইলের নামের ঘরে নামের **শুরুতে** লিখুন `.github/workflows/`। পুরো নাম হবে `.github/workflows/collect.yml`। স্ল্যাশ (/) লিখলে ফোল্ডার নিজে থেকেই তৈরি হয়।
3. **Commit changes** চাপুন।

### ধাপ ৬: গোপন তথ্য (Secrets) দিন
**Settings → Secrets and variables → Actions → New repository secret** এ গিয়ে নিচের secret-গুলো যোগ করুন:

| নাম | মান | প্রয়োজন |
|---|---|---|
| `DRIVE_WEBAPP_URL` | ধাপ ২-এর Web app URL | আবশ্যক |
| `DRIVE_TOKEN` | ধাপ ২-এর গোপন শব্দ (হুবহু একই) | আবশ্যক |
| `GOOGLE_MAPS_API_KEY` | Google Maps API key | ঐচ্ছিক, তবে গবেষণার জন্য ভালো (নিচে দেখুন) |
| `ANTHROPIC_API_KEY` | Claude API key | ঐচ্ছিক, প্রতিদিনের বাংলা AI ব্যাখ্যার জন্য |

### ধাপ ৭: অনুমতি দিন
**Settings → Actions → General → Workflow permissions** এ গিয়ে **Read and write permissions** বেছে নিন এবং **Save** চাপুন।

### ধাপ ৮: চালু করুন 🚀
1. **Actions** ট্যাবে যান। কিছু জিজ্ঞেস করলে সবুজ বাটনে চাপ দিয়ে workflow চালু করুন।
2. বাঁ পাশ থেকে **Dhaka traffic collector** বেছে নিন, তারপর **Run workflow → Run workflow** চাপুন।
3. ৩–৫ মিনিট পর Drive-এ `Dhaka Traffic Snapshots` ফোল্ডারে প্রথম ছবি দেখা যাবে।

এই মুহূর্ত থেকে ৩০ দিন গোনা শুরু হয়। ৩০ দিন পর সিস্টেম নিজেই থেমে যাবে।

### ধাপ ৯: ড্যাশবোর্ড চালু করুন (প্রথম ছবি আসার পর)
1. **Settings → Pages** এ যান।
2. Source হিসেবে **Deploy from a branch** দিন, Branch হিসেবে **main** আর ফোল্ডার হিসেবে **/docs** দিন, তারপর **Save** চাপুন।
3. ১–২ মিনিট পর আপনার লিংক কাজ করবে: `https://আপনার-ইউজারনেম.github.io/dhaka-traffic/`। লিংকটি ফোনের হোম স্ক্রিনে যোগ করে রাখতে পারেন।

### ধাপ ১০: প্রথম দিনেই যাচাই করুন ✅
ড্যাশবোর্ডের নিচে দুটি ছবি থাকে:
- **সর্বশেষ স্ন্যাপশট:** এতে রাস্তায় সবুজ, কমলা ও লাল রঙ দেখা যাচ্ছে কি না দেখুন।
- **বিভাগের সীমানা:** রঙিন অংশগুলো (DMP বিভাগ) আর হালকা ধূসর অংশগুলো (বাইরের এলাকা) সঠিক জায়গায় পড়েছে কি না দেখুন।

কোনো বিভাগের সীমানা ভুল মনে হলে GitHub-এ `config.py` খুলে ✏️ চাপুন এবং সংশ্লিষ্ট থানার অক্ষাংশ ও দ্রাঘিমাংশ (lat, lng) ঠিক করুন।

## Google Maps API key কেন ভালো (ঐচ্ছিক)

key ছাড়া সিস্টেমটি সাধারণ google.com/maps পেজের ছবি নেয়। সেখানে দোকানের আইকন বা লেবেলের রঙ মাঝে মাঝে হিসেবে ঢুকে যেতে পারে। key দিলে সিস্টেম ধূসর মানচিত্রের উপর শুধু ট্রাফিক রঙ দেখায়, তাই হিসাব বেশি নির্ভুল হয়। এছাড়া এটি Google-এর অফিসিয়াল পদ্ধতি, যা গবেষণাপত্রের রিভিউয়ারদের কাছে বেশি গ্রহণযোগ্য।

key পেতে Google Cloud Console-এ **Maps JavaScript API** চালু করতে হয়, আর সেজন্য বিলিং অ্যাকাউন্টে আন্তর্জাতিক কার্ড যোগ করতে হয়। মাসিক ফ্রি সীমার মধ্যে এই ব্যবহার সাধারণত পড়ে যায়, তবে সর্বশেষ মূল্য তালিকা নিজে দেখে নিন। key-এর **Application restriction: None** এবং **API restriction: Maps JavaScript API** রাখুন।

## সংগৃহীত তথ্যের ফাইল

| ফাইল | যা আছে |
|---|---|
| `data/snapshots.csv` | প্রতিটি স্ন্যাপশটে প্রতিটি বিভাগের সবুজ, কমলা, লাল ও গাঢ় লাল পিক্সেল সংখ্যা এবং স্কোর |
| `data/thana.csv` | একই তথ্য থানা ও এলাকাভিত্তিক (DMP-এর ৫০টি থানা ও বাইরের ৯টি এলাকা) |
| `data/daily_summary.csv` | প্রতিদিনের গড়, পিক সময়, সবচেয়ে খারাপ বিভাগ, বৃষ্টি, ছুটি, সংবাদের ট্যাগ এবং কারণ |
| `data/state.json` | শুরুর সময় এবং শেষ স্লট নম্বর |

`slot` নম্বর দেখে বোঝা যায় কোনো স্ন্যাপশট বাদ পড়েছে কি না। slot 0 প্রথম ছবি, slot 1 তার 9.6 মিনিট পরের ছবি, এভাবে চলতে থাকে।

## জানা সীমাবদ্ধতা
- **রানের পালাবদল:** GitHub-এর একটি রান সর্বোচ্চ ৬ ঘণ্টা চলতে পারে। তাই সিস্টেম প্রতি ~৫ ঘণ্টা ৪০ মিনিট পর নিজেই পরের রান চালু করে। পালাবদলের সময় কদাচিৎ একটি স্ন্যাপশট বাদ পড়তে পারে। কোনটি বাদ পড়েছে তা slot নম্বর দেখে বোঝা যায়।
- **রানের চেইন থেমে গেলে:** কোনো কারণে চেইন থেমে গেলে প্রতি ৩ ঘণ্টায় একটি নিরাপত্তা-রান আবার চালু করে দেয়।
- **কারণ নিশ্চিত নয়:** সিস্টেম যে কারণগুলো দেখায় তা "সম্ভাব্য", নিশ্চিত নয়। গবেষণাপত্রে এগুলোকে পারস্পরিক সম্পর্ক (correlation) হিসেবে লিখুন, কারণ-প্রমাণ (causation) হিসেবে নয়।
- **Google-এর শর্তাবলি:** স্বয়ংক্রিয়ভাবে Google Maps-এর স্ক্রিনশট নেওয়া Google-এর শর্তাবলির সাথে সাংঘর্ষিক হতে পারে। গবেষণাপত্রের পদ্ধতি অংশে বিষয়টি উল্লেখ করুন। অফিসিয়াল API key ব্যবহার করা তুলনামূলক নিরাপদ।
